<objective>
Transformar a varredura de segredos em **gate real de merge** e ligar a camada complementar da
plataforma.

Purpose: fecha CFG-01 no nível de processo. Um job verde que não bloqueia merge não é gate (D-09). E
o Secret Scanning nativo cobre o vetor que o gitleaks escopado ao PR não cobre — o push direto —
por custo zero em repositório público (D-11).

⚠️ **Ordem obrigatória (D-14, uma via só):** com `enforce_admins: true`, adicionar o contexto
`secrets` aos required checks **antes** de ele existir na `main` trava TODO PR permanentemente —
inclusive o que traria a correção, e nem admin faz bypass. Por isso a Task 1 é um checkpoint humano
bloqueante que confirma o merge.

Output: branch protection com 3 contextos, 3 toggles de Secret Scanning ligados, runbook atualizado.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| contribuidor → `main` | O merge é o último ponto onde um segredo pode ser barrado automaticamente |
| operador → configuração da plataforma | Branch protection e Secret Scanning não são versionados; só o runbook os torna auditáveis |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-03-GATE-02 | Denial of Service | required check inexistente travando todo PR permanentemente | mitigate | Checkpoint humano bloqueante (Task 1) confirmando que o contexto já reportou na `main` antes do `PUT` (D-14 / Pitfall 6) |
