## Directory Purposes

**`backend/src/`:**
- Purpose: All backend application code
- Contains: Server bootstrap, domain modules (flat files, no subfolders except `routes/` and `middleware/`), route handlers
- Key files: `index.js` (entry), `db.js` (data layer), `agendor.js` (external API + business rules)

**`backend/src/routes/`:**
- Purpose: One file per REST resource/feature area; each exports an `express.Router()`
- Contains: Route handler functions with inline validation and response shaping
- Key files: `auth.js` (largest, includes rate limiting + admin gating), `notifications.js` (test/manual-trigger endpoints)

**`backend/src/middleware/`:**
- Purpose: Express middleware shared across routes
- Contains: Currently only `auth.js` (JWT gate)

**`backend/test/`:**
- Purpose: Backend safety-net test suite — the project's stated "Core Value" (never regress silently on who gets notified)
- Contains: `*.test.js` files run by Node's native `node --test` runner (no Jest/Mocha/Vitest); `setup.js` (env presets, no actual tests); `helpers/` (I/O fakes); `fixtures/` (real anonymized + synthetic Agendor API payloads)
- Key files: `agendor.getStaleDeals.test.js` and `agendor.realsample.test.js` cover the core stale-deal/notify-eligibility logic; `auth.test.js` covers login security; `db.dedup.test.js` covers the same-day notification dedup guarantee
- Naming: `<module-under-test>.<behavior>.test.js` (e.g., `agendor.funnel.test.js`, `agendor.pure.test.js`) — multiple test files may target the same source module (`agendor.js` has five)

**`backend/scripts/`:**
- Purpose: One-off/maintenance scripts not part of the running app or the test suite
- Contains: `capture-fixtures.js` — pulls live Agendor API data and anonymizes it into `test/fixtures/`; raw (`*.raw.json`) captures are gitignored, only the anonymized `*.sample.json` is committed after human review (see `.gitignore` comments)

**`backend/coverage/`:**
- Purpose: `c8` coverage report output (text + lcov), generated by `npm run test:coverage`
- Generated: Yes (gitignored)

**`frontend/src/components/`:**
- Purpose: One component per tab/major UI feature, self-contained (own `fetch()` calls, own local state)
- Contains: `.jsx` files, no further nesting, no shared hooks/ or lib/ directory
- Key files: `Dashboard.jsx`, `DealsList.jsx`, `ReportPanel.jsx`, `ConfigPanel.jsx`, `NotificationHistory.jsx`, `LoginPage.jsx`, `ChangePasswordModal.jsx`

**`deploy/`:**
- Purpose: Shell scripts, docs and nginx config for production server setup, not invoked by the app itself
- Contains: `instalar.sh` (provisioning), `backup.sh` (DB backup cron target), `nginx.conf` (reverse proxy), `branch-protection.md` (runbook for GitHub required-status-check setup, references the CI job IDs in `.github/workflows/ci.yml`)

**`logs/`:**
- Purpose: Runtime log output directory, created automatically by `backend/src/index.js` if missing
- Contains: `access.log` (morgan combined format), `error.log` (uncaught error stack traces)
- Generated: Yes (gitignored via `*.log`)

**`.github/workflows/`:**
- Purpose: CI pipeline definition
- Contains: `ci.yml` — two parallel jobs (`backend`, `frontend`), triggered on every pull request and push to `main`; job IDs (not `name:` fields) are the GitHub required-status-check contexts, so job IDs must not be renamed casually (see `deploy/branch-protection.md`)

## Key File Locations

**Entry Points:**
- `backend/src/index.js`: Backend HTTP server bootstrap
- `frontend/src/main.jsx`: Frontend React mount point
- `iniciar.sh` / `ecosystem.config.js`: Process startup (shell script / PM2)

**Configuration:**
- `backend/.env` / `backend/.env.example`: Environment variables (SMTP defaults, `AGENDOR_TOKEN`, `JWT_SECRET`, `ADMIN_USERS`, `SEED_ADMIN_EMAIL/PASSWORD`, `BASE_URL`, `ALLOWED_ORIGINS`, `DB_PATH` override)
- `frontend/vite.config.js`: Dev server port/proxy, build output
- `biome.json` (repo root): Lint + format rules shared by both `backend` and `frontend` (each has its own `lint`/`format` npm scripts that invoke the same shared config)
- `backend/.c8rc.json`: Coverage-gate thresholds enforced by `npm run test:coverage` and CI
- Runtime app config (SMTP creds, cron schedule, stale-day threshold): stored in SQLite `config` table, edited via `backend/src/routes/config.js` and `frontend/src/components/ConfigPanel.jsx` — NOT in files

**Core Logic:**
- `backend/src/agendor.js`: Business rules for what counts as a "stale deal" (category/owner/stage exclusions, notify-eligibility)
- `backend/src/scheduler.js`: Orchestration of daily/weekly automated runs
- `backend/src/db.js`: All SQL and schema

**Testing:**
- `backend/test/*.test.js`: Backend test suite (8 files as of this analysis), run via `node --test` (`npm test`) or under coverage (`npm run test:coverage`)
- `backend/test/setup.js`: Must-load-first env presets (guards `secret.js`/`db.js`/`agendor.js` require-time side effects)
- `.github/workflows/ci.yml`: Runs the backend test suite (with coverage gate) and the frontend build on every PR/push to `main`
- Frontend has no test suite; `frontend/package.json`'s `test` script is an explicit no-op placeholder (`echo "(frontend sem testes nesta fase — gate é vite build)" && exit 0`) — the frontend CI gate is `vite build` only

## Naming Conventions

**Files:**
- Backend: lowercase, single-word or `camelCase.js` module names (`agendor.js`, `emailer.js`, `scheduler.js`); route files named after the resource (`deals.js`, `config.js`)
- Backend tests: `<module>.<aspect>.test.js`, always inside `backend/test/` (flat, not co-located with source)
- Frontend: `PascalCase.jsx` for every React component file, matching the exported component name (`Dashboard.jsx` exports `Dashboard`)

**Directories:**
- Lowercase, plural for collections of similar files (`routes/`, `components/`, `helpers/`, `fixtures/`), singular for single-purpose (`middleware/`, `scripts/`)

**Functions (backend):**
- `camelCase`, verb-first for actions (`getStaleDeals`, `sendStaleNotification`, `scheduleTask`, `logNotification`), `get`/`set` prefix convention for config/data accessors in `db.js`

**Database:**
- Table names: `snake_case` (`notification_log`, `weekly_snapshots`, `app_users`, `reset_tokens`, `login_logs`)
- Columns: `snake_case`

**React components:**
- Functional components only, `export default function ComponentName()`
- Props destructured in function signature (e.g., `function Dashboard({ onTabChange })`)

## Where to Add New Code

**New API Endpoint:**
- Add a new route file under `backend/src/routes/` (e.g., `routes/foo.js`) exporting an `express.Router()`, then mount it in `backend/src/index.js` under `/api/foo`
- If it needs new business logic, add functions to `backend/src/agendor.js` (Agendor data) or a new domain module — avoid inlining heavy logic directly in the route file (see the Anti-Patterns section of `ARCHITECTURE.md`)
- Add a corresponding `backend/test/<module>.<aspect>.test.js` file if the endpoint touches notification eligibility, dedup, or auth — this is the project's core-value safety net, not optional polish

**New Database Table/Field:**
- Add `CREATE TABLE IF NOT EXISTS` DDL and any `ALTER TABLE` migration statements to `backend/src/db.js` (follow the existing pattern: wrap `ALTER TABLE` in `try/catch` since better-sqlite3 has no migration framework)
- Add corresponding accessor functions in `db.js` and export them in the `module.exports` block at the bottom
- If the table/column feeds into notification dedup or delivery, add/extend a test using `backend/test/helpers/tmpDb.js` (mirrors `backend/test/db.dedup.test.js`)

**New Frontend Tab/Feature:**
- Create `frontend/src/components/NewFeature.jsx` following the self-contained pattern (own `fetch()` calls, own `useState`)
- Register it in `frontend/src/App.jsx`: add to the `TABS` array and add a `{tab === 'newfeature' && <NewFeature />}` line in the `<main>` render block

**New Scheduled Job:**
- Add the job function to `backend/src/scheduler.js`, register it with `cron.schedule(...)` inside `scheduleTask()`, and add a `.stop()` call for it in `stopTasks()` for graceful shutdown

**New Backend Test:**
- Add a `backend/test/<module>.<aspect>.test.js` file; it will be auto-discovered by `node --test` (no config/registration needed)
- If the test needs the Agendor HTTP boundary, use/extend `backend/test/helpers/fakeAxios.js` rather than adding a new mocking library
- If the test needs a SQLite instance, use `backend/test/helpers/tmpDb.js` or set `process.env.DB_PATH` before requiring `db.js` — never point tests at the real `backend/agendor.db`
- New fixtures with real Agendor data must go through `backend/scripts/capture-fixtures.js` and be anonymized/reviewed before committing as `*.sample.json`; raw captures (`*.raw.json`) must never be committed (enforced by `.gitignore`)

**Shared Utilities:**
- No dedicated `utils/` or `lib/` directory exists on either side. Backend shared helpers currently live directly in the domain module that uses them (e.g., URL-safety checks in `emailer.js` and `track.js` are duplicated, not shared) — if adding a cross-cutting helper, prefer a new top-level module in `backend/src/` (e.g., `backend/src/utils.js`) over duplicating logic.

## Special Directories

**`backend/node_modules/`, `frontend/node_modules/`, root `node_modules/`:**
- Purpose: Installed dependencies (three separate `package.json`/`node_modules` trees: root, backend, frontend)
- Generated: Yes
- Committed: No (gitignored)

**`backend/coverage/`:**
- Purpose: `c8` text + lcov coverage report, produced by `npm run test:coverage`
- Generated: Yes
- Committed: No (gitignored)

**`logs/`:**
- Purpose: Runtime access/error logs written by `morgan` and the global error handler
- Generated: Yes (directory auto-created by `backend/src/index.js` if missing)
- Committed: No (`*.log` gitignored)

**`.claude/worktrees/`:**
- Purpose: Git worktree(s) created by Claude Code tooling for parallel work (e.g., `goofy-bose-c4e1ec`), mirrors backend/frontend structure
- Generated: Yes (tooling artifact, not part of the application)
- Committed: No (`.claude/` gitignored)

**`unpacked/`, `slides_screenshots/`:**
- Purpose: Extracted PowerPoint XML and screenshot exports used for building presentation decks
- Generated: Yes
- Committed: No (gitignored)

**`.planning/`:**
- Purpose: GSD planning artifacts including this codebase map (`.planning/codebase/`)
- Generated: Yes (by GSD tooling)
- Committed: Repository-dependent (not addressed by `.gitignore`)

**`backend/test/fixtures/`:**
- Purpose: Committed test data — one anonymized real-world sample (`real-deals.sample.json`) and one hand-built synthetic page (`synthetic/deals-page.json`)
- Generated: Partially (synthetic fixture is hand-authored; the real sample is captured then anonymized via `backend/scripts/capture-fixtures.js`)
- Committed: Yes for `*.sample.json`; No for `*.raw.json` (gitignored, contains PII/token — must never be committed)
